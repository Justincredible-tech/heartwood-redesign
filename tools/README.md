# Heartwood optimized static build

Edit the readable files under `../source/`, not generated assets in publish:
- `source/heartwood-site.html`: markup and artwork.
- `source/css/heartwood-site.css`: site/artwork styles.
- `source/css/fonts.css` and `source/assets/fonts/`: exact self-hosted font subsets and their licenses.
- `source/js/heartwood-site.js`: content and interactions.
- `source/mobile/`: phone page/state code, paper-art generator, reviewed PNG masters and preencoded AVIF/WebP assets.
- `source/taste/`: desktop night artwork and optional interactions, composed from the current author source.
- `source/assets/logos/heartwood-logos.svg`: theme-aware vector symbols made from the final supplied logos. Exact renamed originals remain alongside it for provenance. Symbols are embedded once in the HTML so the page keeps its standalone entry behavior.

From this tools directory:

```powershell
npm ci --ignore-scripts --no-fund
npm run build
python preview.py --port 8001
```

With the preview running, `python test-delivery.py` checks artwork/content preservation, compression round trips and real HTTP delivery. It targets `http://127.0.0.1:8001/` unless `HEARTWOOD_PREVIEW` names another preview; use your own preview port, because another copy of this project may hold 8001 and the tests would then quietly check that copy instead. `python preview-baseline.py` optionally exposes only the three preserved original site assets on loopback8002 for paired performance comparisons; it never serves the evidence directory.

The ordinary build needs Node 22 or newer and the packages locked in package-lock.json. It runs the site author’s readable build in one process; Node’s built-in zlib supplies verified Brotli/gzip compression. Python with Brotli is needed for the delivery tests, preview and upload packaging. No npm package is used in the browser. Builds are offline after the locked dependencies are installed.

Build emits content-fingerprinted minified CSS/JS, an optimized HTML entry point, unchanged WOFF2 fonts and licenses, and verified lossless `.br` / `.gz` text variants. It preserves inline artwork styles, geometry and event handlers. The preview serves only generated public assets, listens only on loopback, refuses occupied ports, negotiates compression, sends representation-specific ETags and never lists directories.

Use the compressed preview at http://127.0.0.1:8001/ (or the port you started it on) for delivery measurements. It maps the root to the assetless scene selector; `heartwood-site.html` remains a desktop body alias. The old `python -m http.server` preview does not negotiate compressed files. Local tests do not prove the production host enables Apache rewrite, headers or MIME overrides.

The build composes all three experiences in one run. `experience-entry.html` chooses desktop day, desktop night or phone before scene resources load. The main entry follows the system preference on desktop and phone. `taste/` starts at night on both; `?theme=light` selects day and `?theme=dark` selects night explicitly. `?view=desktop` requests the desktop composition on a phone. Query/fragment state survives selection and mode changes. `desktop-day.html` and `taste/scene.html` are render documents whose history addresses are canonicalized to the public entry. `mobile/index.html` is an assetless selector for the fixed `mobile/day.html` and `mobile/night.html` outputs.

Run `python test-responsive-build.py` for the responsive source/output and entry-routing contracts. Run `python test-taste-source.py` for all five desktop taste source contracts, including authored motion/geometry and theme isolation. Both are bounded source tests with complete-run checks; they do not start browsers or establish visual, device or performance acceptance.

Phone builds read content, vector logos, fonts and the three favicon forms from the author source, with local approved photos and paper recipes. They verify exact input hashes, all 25 master document/PNG identities and each encoded asset's hash/size before copying it. They emit both fixed themes, a shared behavior script, fingerprinted assets and `mobile/manifest.json`. Ordinary builds need no browser or image encoder and do not fetch remote assets or regenerate caches.

Art regeneration is a separate, opt-in command: `node regenerate-mobile-art.mjs --plan --only roots,roots-night` inspects affected recipes without native dependencies. See [`../docs/MOBILE-ART.md`](../docs/MOBILE-ART.md) for reviewed rendering and application commands and their current macOS-only native requirements. If `source/mobile/art.mjs`, its referenced paper recipe or shared night mapping changes a document, render that affected document at 3x, regenerate its 2x/3x AVIF and WebP derivatives with the existing manifest settings, and update `masters.json` plus the encoded manifest together. Deliberately changed pinned inputs also need their reviewed hashes updated in `mobile-source-inputs.mjs`. Regenerate the crown mask when the arrival tree changes. Review both themes and phone orientations; renderer/encoder versions can change raster bytes even with identical recipes, so retain the recorded hashes rather than claiming cross-toolchain byte reproducibility. The arrival tree currently keeps 200 leaves and enlarges only its visible paper faces by 18%; its original backing silhouette and category-branch artwork remain unchanged.

The publish `.htaccess` follows Apache's [precompressed delivery guidance](https://httpd.apache.org/docs/2.4/mod/mod_deflate.html#precompressed). Apache must permit these directives; test HTTP status, Content-Type, Content-Encoding, Vary, cache invalidation and decoded content on staging before deploying. Content-fingerprinted assets may be cached for a year; HTML revalidates so rebuilds select the new fingerprints. Do not copy agents, Conductor metadata, internal review evidence, tools, node_modules or source into the public release directory.

Do not run `vendor-fonts.py` for ordinary rebuilds. It is an explicit asset-import step: downloads the original Google font CSS/WOFF2 files and SIL licenses, preserves Latin and Latin-ext coverage, and records exact URLs/hashes in font-provenance.json. Reimporting later could change a font version and requires visual review.

Browser visual/performance/regression evidence and before-sources live under `../review-evidence/003-performance-20261012/`. No production deployment or human release approval is implied.

Photos: the Heartbeat cover and Forest Council poster use the site author's local, content-hashed 360, 720 and 1080 px WebPs in `source/assets/photos/`; their links still go to heartwood.org. For a new issue or poster, supply every authored photo address and its locally downloaded original to `tools/import-photos.py --out <new review folder>`, using the existing pinned Pillow12 environment through the offline `uv` command in [PHOTO-IMPORT.md](PHOTO-IMPORT.md). Keep the sibling `photo-import-runtime.py` with it. The tool validates and reuses unchanged approved derivatives byte-for-byte, or prepares full-image quality86 renditions and proposed JavaScript/provenance/assets as a bounded, owned review bundle. Review and copy those proposals into source as one change; it never downloads, edits source in place or deletes unrelated WebPs. Updating phone-specific photos also requires the corresponding original URL/hash and reviewed rendition mapping in `mobile-source-inputs.mjs`; this importer does not regenerate phone artwork. The six adopted author WebPs are unchanged. Original author evidence: `../review-evidence/016-fork-performance-fixes-20261013/`.

Final logo evidence lives under `../review-evidence/004-final-logos-20261012/`. `python import-logos.py` regenerates the symbols from the two supplied files in `../finalLogos/`, verifies path geometry/transforms against the originals, and changes only the monochrome fill to currentColor for theme contrast. It updates the two inline logo symbols in the readable source HTML without changing other artwork. Final supplied files remain intact. Scoped desktop/mobile logo visual acceptance passed after the browser connection recovered during track005.

Paper grain: `--grain-fine` in the stylesheet is the recipe for the flecks and fibres. `python render-grain.py` has Chrome draw exactly that recipe into a 256px lossless WebP tile for each common screen density, saves them to `source/assets/grain/` with content hashes and a provenance file, and points the stylesheet's `--grain-tile` declarations at them. The build copies the tiles and preloads only the one each screen density uses. Rerun it after editing the recipe; `test-delivery.py` fails while the tiles are older than the recipe. It needs Python Playwright with installed Chrome, and Pillow. Measurements and the visual comparison are in `../review-evidence/007-grain-and-motion-20261012/`.

Decoration density evidence is in `../review-evidence/005-decoration-density-20261012/`: exact populations/removals, source review, delivery results and settled browser screenshots. Whole decorative nodes were removed from source; remaining shapes and motion are unchanged. Stable `stone--tablet-hidden` / `stone--phone-hidden` classes preserve each retained rock's original responsive visibility instead of relying on its new ordinal. The one-shot helper in the evidence folder is archival, not part of normal builds.

For a clean server upload snapshot, run `npm run build` then `python package-upload.py`. The default output is `../publish/upload-ready/`; upload its contents, including hidden `.htaccess`, into the server's site directory. By default it packages the client showcase: the homepage `index.html` is the design-concepts landing page from `../showcase/index.html`, `living-tree.html` is the assetless scene entry, and `desktop-day.html`, `taste/` and `mobile/` supply its scene documents. The packaged desktop body records `living-tree.html` as its canonical main entry and receives matching recompressed text variants; it is not promised byte-identical to the raw build body. The alternative designs from `../mockups/` go to `mockups/`, and the landing page's preview images from `../showcase/previews/` go to `assets/previews/`. The landing page and mockups get verified `.br` / `.gz` variants, and packaging stops if any link or image on the landing page points outside the package. Once the client has chosen, `python package-upload.py --site-only` packages the scene entry as `index.html` with the same desktop/taste/phone documents. Only allowlisted public assets, scene files, showcase files and configuration are copied. Instructions, source, tools and evidence stay outside the upload folder.

Packaging never overwrites an existing snapshot; use `python package-upload.py --name upload-ready-v2` for a new one after later edits. The generated file/hash manifest stays in tools/upload-package-manifest.json. Server-specific Apache/compression and existing remote-content availability still require host verification; creating this folder performs no deployment.

## Public checks and optional supervision

`npm test` runs the required portable public tests and identifies optional native art suites separately. `npm run test:native-art` requests the macOS process/transaction checks; `npm run test:native-art-toolchain` also requests the optional renderer/encoder checks and their explicitly supplied dependencies. An unsupported requested native host fails; an ordinary build does not need those dependencies. Native Windows execution has not been verified in the current development environment.

The required portable checks, the optional browser setup and their failure semantics are documented in [`../docs/TESTING.md`](../docs/TESTING.md).

`npm run build:supervised` adds the multiprocess watchdog around the normal build; `npm run build:phone:supervised` does the same for phone composition. `npm run build` and `npm run build:phone` stay direct, readable commands with an in-process deadline and no parent-process watcher. `npm run test:delivery -- --receipt <new-file.json>` validates the exact staged Git tree in an owned clean folder, installs the lockfile, runs the normal build and required public tests, then runs the author’s HTTP delivery checks against its own preview. Its receipt names the tested tree; changes require a new receipt. The receipt path must be new, and `--offline` requires the npm lockfile packages to be cached already.


The required public roster includes the Python regressions in `tests/*.test.py`; `npm test` loads their filenames directly and rejects empty, skipped or incomplete runs. Python must be installed with the dependencies in `requirements.txt`. It defaults to `python`; PowerShell users who select the Python launcher can set `$env:HW_PUBLIC_TEST_PYTHON = "py"` and `$env:HW_PUBLIC_TEST_PYTHON_ARGS = '["-3"]'`. These variables select an executable and a JSON argv array, with no shell interpolation. For a delivery run, `--python <executable>` and repeated `--python-arg <argument>` select the same interpreter for both public regressions and HTTP delivery checks.
