# Maintaining local photos

`import-photos.py` prepares a new review folder. It never downloads originals, writes source files in place, removes old WebPs or starts a browser. Download originals yourself, then pass every literal `img.src: ORIGIN + '/…'` photo in the authored JavaScript exactly once. Original URLs remain the PHOTOS keys and the destinations of links.

With the project's existing pinned Pillow environment:

```sh
uv run --offline --no-project --no-sync -- .venv/bin/python tools/import-photos.py --out /path/to/new-photo-review-folder https://heartwood.org/events/forest-council/2026-forest-council.jpg /path/to/poster.jpg https://heartwood.org/heartbeat/Fall-2026.jpg /path/to/cover.jpg
```

On Windows use `.venv\Scripts\python.exe`. To provision only the photo encoder explicitly instead of the grain/browser dependencies, use `uv run --no-project --with pillow==12.0.0 python tools/import-photos.py …`. That command can acquire Pillow; the importer itself makes no network requests. `--help` is stdlib-only. `--plan` validates the complete input set/hashes without retaining output; new originals are marked `ENCODING_REQUIRED`, with their dimension/profile checks reserved for bounded encoding.

Review `import-receipt.json`, the proposed `heartwood-site.js`, `photos-provenance.json` and all listed WebPs. Copy the proposed JavaScript into `source/js/`, and the provenance and listed WebPs into `source/assets/photos/` as one reviewed change. Preserve unrelated author files. Old unreferenced derivatives may be removed manually after checking their old provenance and references; the tool never guesses that every `.webp` belongs to it. Source application is explicitly `NOT_APPLIED`; automatic multi-file application is not implemented.

The recipe remains full-image EXIF transpose, plain sRGB RGB/L without embedded ICC, Pillow Lanczos, widths 360/720/1080, Python round for height, quality86, method6. New encoding requires Pillow12.0.0 and records the actual WebP codec version. Originals must be bounded regular files <=16MiB/32MP, with at least360px width. Existing derivatives are reused byte-for-byte when source SHA/size, actual original-header dimensions/orientation, recipe widths/heights, encoded hash/size and WebP header dimensions agree. JPEG metadata reuse needs no Pillow import; non-JPEG metadata uses pinned Pillow without rebaking. Their legacy encoder toolchain is `UNPROVED_LEGACY`; matching bytes do not establish a historical encoder version.

Keep the sibling `photo-import-runtime.py` with the importer. It supplies the stdlib-only, file-backed guardian and worker; the ordinary photo command requires neither Node, Chrome nor a compiler. It uses no multiprocessing bootstrap or resource tracker. Inputs are technically restricted to JPEG, PNG and WebP signatures, with the matching Pillow decoder selected explicitly. Other formats are unsupported, including formats whose plugins launch external converters. The default CLI worker performs no subprocess launch; this statement does not cover arbitrary replacement callback implementations.

Default limits are120s overall and30s per phase; configurable maxima are300s and60s. They are ceilings, not scheduled waits. Startup admission and complete pipe frames have separate bounds. Watcher threads start before `Popen` or complete-frame input/output; they watch the original launcher and phase deadline while the caller is waiting. Messages are capped at4MiB, queues at16 frames, and paths/URL fields at4KiB UTF-8. POSIX roles use separate sessions and live parent checks. Windows source uses retained process handles and creation times; native execution, reparse/UNC/long-path behavior and the initial client handle-acquisition interval remain unverified.

The guardian retains actual child handles and admits each output file before the worker writes it. Error, timeout or stop retires owned children and removes an uncommitted bundle only if its recorded directory, marker and file identities still match. Unexpected files or changed identities are preserved and reported as failures. A complete bundle is retained only after the worker exits successfully, its result/file hashes are admitted, and the client commits it. Death after that commit may leave the valid review artifact; it is not an abandoned temporary folder. No source files are applied automatically. Existing/foreign destinations are rejected, and legitimate existing-parent aliases such as macOS `/tmp` are canonicalized before admission.

Focused Mac receipts cover the actual retained-byte CLI, invalid flags/help, a held-open incomplete startup frame, a CPU phase timeout, stop signals, original launcher death and cleanup when the API returns to a living caller. The fixture bytes establish metadata/cache and lifecycle behavior, not fresh image decoding or browser fidelity. Native Windows/Linux lifecycle and new encoding under the exact pinned12.0 environment are `NOT_RUN`. The interpreter/kernel interval before file entry, arbitrary blocked native code, complete package/native dependency epochs and arbitrary custom callbacks are outside that proof. These limits must not be described as a universal never-hang certification.

Bundle modes and marker are temporary review ownership metadata. This workflow does not apply source directories, rewrite unrelated permissions/xattrs/ACLs or certify browser rendering, crop perception, performance or physical-device behavior. The six approved upstream WebPs are retained unchanged in this correction.
