# Optional mobile art dependencies

Ordinary page builds use Node only and reuse reviewed mobile assets. Explicit regeneration additionally uses the locked Playwright-core1.64.0 and Sharp0.35.5 packages here and an operator-selected installed Chromium executable. Install this separate optional package with `npm ci --prefix tools/mobile-art`; no browser download or dependency installation happens inside a render job.

The public runtime is `tools/mobile-art-runtime.mjs`. It owns independent parallel CLI jobs, native process identity, scratch, browser RPC, profiles, contexts and outputs. It requires Node22+, macOS and installed command-line compiler tools. Native rendering/application ownership on Windows/Linux is unsupported; ordinary Node-only builds are unaffected. Output publication currently requires the same filesystem as owned `/private/tmp` scratch. Unsupported or missing prerequisites fail; they never become an acceptance pass.

Use a dedicated Node CLI worker for each active job. One callback per worker is supported because token/TMP environment is scoped for the job; unrelated concurrent managed work in that same worker is outside this contract. Separate CLI workers run independently without a queue. Completed callbacks restore their environment and remove their own signal handlers before returning.

`runOwnedArtJob(options, operation)` supplies pinned local rendering/encoding helpers. `runOwnedArtTransaction(options, operation)` supplies source application without loading a browser or encoder. Create outputs through `ensureOutputDirectory(path,{reason})`, which returns the authentic inode/marker ownership record; `registerOutput` can revalidate that existing record. Raw mkdir followed by registration cannot provide death-safe ownership and is rejected. A complete render bundle is retained only after authenticated successful completion, including cleanup. Dead/failed jobs remove their exact provisional output.

Art application registers full original/new file and directory censuses and uses `moveArtTransaction` for each no-replace directory move. The guardian retires an abandoned worker before filesystem recovery, restores an exact original backup or retains complete promoted art, and preserves unexpected or concurrently edited author data as a failure. A failure may leave a changed author backup for recovery; it is never silently deleted. Source application is separate from regeneration and does not establish visual acceptance.

Embedded toolchain receipts contain relative labels, versions and hashes, without run tokens, PIDs or host/private paths. They record the installed package/native closure, Node and public helper bytes. They do not attest OS system libraries, GPU drivers, the complete compiler SDK or physical-phone fidelity. Local native helper artifacts and detailed ownership reports live in ignored `.cache/`; they are neither source assets nor files to publish.

Resource-free validation is `node --test tests/public-art-runtime.test.mjs`. Optional native lifecycle checks are `node --test tests/public-art-lifecycle.test.mjs` on macOS. Optional encoder/toolchain checks additionally require explicit local `HW_ART_SHARP_MODULE` and `HW_ART_PLAYWRIGHT_MODULE` entry paths and run `node --test tests/public-art-toolchain.test.mjs`; absent prerequisites fail rather than skip. These native checks are separate from ordinary build prerequisites. Independent real renderer and visual review are still required before accepting newly rendered assets.

Optional native jobs use an independent guardian for source/tool admission (up to60seconds per admission phase) and the selected work; regeneration has a660-second total ceiling and application120seconds. These are deadlines, not minimum waits. The guardian allocates and records scratch before exposing it to the worker. Control inputs are regular, descriptor-bounded reads: Csource1MiB, nativebinary2MiB, registry8MiB, small manifests/timeouts8KiB and ownership markers4KiB.

New native receipts record both the lifecycle core and the actual optional caller/direct public composer and planning input bytes. Complete successful bundles require a matching final disk epoch, and every new renderer/encoder SHA reference must resolve to the canonical receipt. Old retained bytes with no native history remain explicitly unproved; no past renderer history is invented.

Application preserves supported regular-file and directory permission modes, including executable/read-only files and empty Unicode directories. Read-only roots and nonempty read-only directories fail before replacement because marker/backup cleanup is not yet supported safely. Owner, ACL, extended attributes, timestamps and hardlink relationships are not copied or attested.

Optional art commands and preparation APIs currently require the selected project to be the same real canonical project as their executing tools. `--root` may use a canonical alias of that project; another project is rejected before source imports/reads or native work. Run that other project’s own copied tools there until true target-module loading is implemented. The co-location helper is included in optional source and producer disk receipts. Current ordinary page composition declares20 inputs, including the foreground launcher, encoded-art validator and inert bounded-result admission module. A source-closure change requires a fresh current composition receipt; an older receipt declaring18 or19 inputs does not establish the new closure. Ordinary composition remains standard-library Node and reuses reviewed art bytes.

Art recovery follows actual directory inodes, including crashes between a move and its phase update. Before the new tree is promoted, recovery keeps or restores the old tree. After the new tree is coherently promoted, recovery may retain that complete new tree even if a later final input-epoch check or COMMITTED update fails; the command still fails and this is not unconditional rollback. Changed or incoherent author/foreign data is preserved and reported as an error. This describes the existing cutover policy, not a newly verified policy defect.
